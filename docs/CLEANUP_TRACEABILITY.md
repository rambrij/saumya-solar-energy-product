## 6. Phase 0 disposition

- Phase 0 was documentation-only. Phase 1 added persisted Spring-event processing for notifications and exports. Three undocumented synchronous file-download routes were removed after the frontend migrated to the SRS export-job contract; the JSON operations-report route and CSV/XLSX/PDF capabilities remain.
- Historical V1–V63 have been consolidated into exactly one `V1__baseline.sql`. The MySQL 8.4 schema comparison in CI run `42877367240` returned an empty diff. The original migration files are retained only in Git history for reproducibility.
- Notifications use persisted pending delivery rows, post-commit Spring application events and tenant-aware scheduled recovery. A provider call that succeeds immediately before a process crash can be repeated after lease recovery; delivery is therefore at-least-once, with a stable tenant/channel idempotency key retained in the database.
- Asynchronous operations exports use persisted tenant-scoped jobs, post-commit Spring application events, private file storage, owner/tenant authorization, expiry and scheduled recovery. The JSON operations-report endpoint remains; synchronous file-download routes were replaced by the asynchronous export-job contract. The current export type is OPERATIONS; expansion to other report families and filter parity remains an open question.
- CMS/blog capability is required by both source documents but no dedicated backend CMS implementation is visible in the current tree. This is a gap to resolve, not a deletion candidate.
